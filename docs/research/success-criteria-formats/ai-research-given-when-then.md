## Source-Supported Description
Gherkin examples express an initial context, an event, and an expected observable outcome. [Cucumber](https://cucumber.io/docs/gherkin/reference/)

## Working Structure
Given context → When action/event → Then outcome

The structure is a concise research adaptation, not a mandatory template quoted from the source.

## Strengths and Limitations; Analysis
- Strength: Makes normal and exceptional behavior concrete and repeatable.
- Limitation: Passing selected scenarios does not demonstrate reliability across all inputs; many scenarios can become repetitive.

## Project Relevance; Analysis
Suitable for grounded answers, unavailable information, conflicting notes, and offline interaction.

## Illustrative Application
> Given no note contains the requested appointment date, when the user asks for it, then the app states that the stored information is insufficient.

This example is authored for comparison. It is not taken from the source and does not establish the project's final criteria or thresholds.

## Useful Lesson
Specify important situations and observable outcomes, then evaluate repeated behavior separately.
